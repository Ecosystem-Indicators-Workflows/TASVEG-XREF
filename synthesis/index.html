11  Synthesis overview

The objective of the synthesis stage (Step 5 of Figure 1.1; IUCN (2025)) is to consolidate validated membership assessments from multiple interpreters into structured summary tables ready for area accounting (Chapter 12) and spatial mapping (Chapter 13 and Chapter 17).

Using the cleaned membership table (TASVEG_clean) as our authoritative input, several explicit design decisions govern how information is aggregated:

  • Elicitation round: select the latest post-discussion round (round == 2), which reflects revised judgements and complete coverage across all five interpreters.
  • Unit of aggregation: aggregate by source unit (VEGCODE) to characterise the target relationship(s) of each TASVEG community.
  • Interpreter treatment: retain each interpreter’s profile separately, or aggregate across all interpreters into a single consensus estimate.
  • Aggregation metric: when aggregating across interpreters, compute the proportion of total membership votes (prop_memb) assigned to each candidate target EFG \(t\) for source unit \(s\): \[\text{prop\_memb}_{s, t} = \frac{\sum_{i} m_{s, t, i}}{\sum_{k} \sum_{i} m_{s, k, i}}\]
  • Candidate retention: keep all non-zero candidates (preserving partial/fuzzy relationships) or retain only the single best candidate (“winner-takes-all”) for categorical maps.
  • Support and weighting metadata: report both the proportion of membership weight (prop_memb) and the number of interpreters assigning positive membership (supporting out of total_interp) so users can filter or weight downstream outputs by confidence.

11.1 Four synthesis table variants

Combining the interpreter and candidate-retention choices yields four distinct summary structures explored below:

Strategy Interpreters Aggregation metric Candidates kept Ranking rule Weighting rule
1. Full Round 2 records All (separate) None All non-zero candidates None (flags best) Individual membership (memb)
2. Aggregated, all candidates Aggregated prop_memb All non-zero candidates None (flags best) prop_memb
3. Best candidate per interpreter All (separate) None Single best per interpreter Highest memb None (“winner takes all”)
4. Best candidate from summary Aggregated prop_memb Single best per VEGCODE Highest prop_memb None (“winner takes all”)

Our setup for this R session loads ecoSynthesis, dplyr, sf, units, and ggplot2, and reads the validated membership table from results/XREFs/memb-tables.rda:

library(sf)
library(ecoSynthesis)
library(dplyr)
library(units)
library(ggplot2)
here::i_am("synthesis/index.qmd")
output_dir <- here::here("../results/XREFs")
load(here::here(output_dir, "memb-tables.rda"))

11.1.1 1. Keep all individual Round 2 records

The first option preserves every validated positive record from Round 2 without aggregating across interpreters. Within each (VEGCODE, expert) pair, we compute the interpreter’s total assigned membership (total_memb), flag their highest-scoring candidate (best), and set unit-level support counters (supporting = 1, total_interp = 1) for schema consistency with aggregated tables:

TASVEG_revised <- TASVEG_clean |>
    filter(round == 2) |>
    group_by(VEGCODE, expert) |>
    mutate(
        total_memb = sum(memb),
        best = memb == max(memb),
        supporting = 1,
        total_interp = 1
    ) |>
    ungroup()

Inspecting AAP (Alkaline pans) shows all individual Round 2 assignments across the five interpreters:

11.1.2 2. Aggregate across interpreters, keeping all candidates

When a single multi-interpreter consensus profile is needed while still preserving fuzzy secondary relationships (for example, to generate the per-EFG membership rasters in Output 2; Chapter 17), we call ecoSynthesis::summarise_membership() with keep_all = TRUE and which_round = 2, then add a best flag identifying each community’s top-ranked EFG:

TASVEG_summary <-
    TASVEG_clean |>
    summarise_membership(keep_all = TRUE, which_round = 2) |>
    mutate(
        best = prop_memb == max(prop_memb),
        .by = VEGCODE
    )
Round nr. 2 selected.
NoteecoSynthesis::summarise_membership() default argument note

In ecoSynthesis v0.0.0.9005, the function signature defaults to keep_all = TRUE, whereas its documentation text describes keep_all = FALSE as the default. Passing keep_all = TRUE or keep_all = FALSE explicitly avoids ambiguity.

rowMeans(aap_mat, na.rm = TRUE) |>
    (\(x) x[x > 0])()

11.1.3 3. Keep the best candidate per interpreter

A third option retains one categorical “best” EFG per (VEGCODE, expert) combination via slice_max(..., with_ties = FALSE, n = 1), preserving inter-interpreter variation in categorical assignments while discarding minority fuzzy weights:

TASVEG_best_revised <-
    TASVEG_revised |>
    slice_max(memb, by = c(VEGCODE, expert), with_ties = FALSE, n = 1) |>
    mutate(keep = "best")

For AAP, all five interpreters agree on TF1.7 as their top candidate, though their individual membership strengths range between 0.8 and 1.0:

11.1.4 4. Keep the single best candidate from the aggregated summary

Finally, for single-layer categorical maps (such as the 90 m Best-Candidate Spatial Synthesis in Output 3; Chapter 17), calling summarise_membership(TASVEG_clean, keep_all = FALSE, which_round = 2) selects the single EFG with the highest prop_memb for each of the 153 eligible TASVEG units:

TASVEG_best_summary <-
    summarise_membership(TASVEG_clean, keep_all = FALSE, which_round = 2)
Round nr. 2 selected.

We save all four synthesis tables (TASVEG_revised, TASVEG_summary, TASVEG_best_revised, and TASVEG_best_summary) to results/XREFs/memb-summaries.rda for downstream area calculations (Chapter 12) and standalone output scripts (Chapter 17):

save(

    TASVEG_summary,
    TASVEG_best_revised,
    TASVEG_best_summary,
    file = here::here(output_dir, "memb-summaries.rda")
)

11.2 Connecting tabular synthesis to spatial outputs

The tabular summaries above serve as intermediate inputs for spatial operations: joining them back to the attribute table of the TASVEG 5.0 polygons (TASVEG_5_0.shp) enables both non-spatial area accounting (Chapter 12) and spatial raster/vector products (Chapter 13). Depending on the output format—a single categorical GeoTIFF, a multi-layer stack of per-EFG membership rasters, or a vector GeoPackage bundle—different amounts of fuzzy and per-interpreter information can be preserved (see Chapter 17).
